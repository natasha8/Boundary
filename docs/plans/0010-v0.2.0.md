# BOUNDARY v0.2.0 Roadmap

- Status: Approved (planning). Implementation not started.
- Version: 0.2.0
- Planned: 2026-08-21
- Depends on: frozen v0.1.0 (Milestones 1–8)
- Decision records: ADR 0001–0008 remain authoritative for delivered
  surfaces. ADR 0009 is planned only for the M10 product surface and is
  written when that milestone is implemented, not before.
- Implementation: not started. This document is the implementation plan.
  Do not treat planned names as shipped APIs.

v0.1.0 is released and frozen. This roadmap does not redesign working
v0.1.0 surfaces without a concrete need.

## Purpose

Define the smallest coherent v0.2.0: a CI-usable uncredentialed passive
scan, plus one explicit two-identity GET comparison that produces an
`AuthorizationObservation`.

v0.2.0 is not a feature dump, not Bug Bounty Mode, and not a UI release.

The product story is:

    CI-ready `boundary scan` (M9)
        + opt-in `boundary compare` (M10)
        + Bug Bounty foundations recorded, not built (M11)

## Product principles (unchanged)

- evidence-driven
- deterministic-first
- Scope Engine is the central authority
- AI never decides scope or vulnerability verdicts
- active/mutating behavior is not silently enabled
- minimal dependencies
- modular monolith
- smallest complete solution
- no speculative abstractions
- tests-first implementation
- authorized targets only

## Non-goals for this document

This file is documentation only until an implementation slice is
approved. It must not be used as permission to:

- modify production code or tests in the same change as this file;
- add dependencies;
- change `pyproject.toml`, README, or CHANGELOG (those are release

## 1. v0.1.0 baseline (implementation facts)

Shipped architecture is a modular monolith
(`docs/decisions/0001-modular-monolith.md`) with one runtime dependency
(`httpcore`). Pipeline:

```text
Target
    -> Scope
    -> Transport
    -> Discovery
    -> Passive
    -> Evidence
    -> ScanResult
    -> Reporting
    -> text / JSON / SARIF
```

### Authorities — do not redesign

- **Scope** (`src/boundary/scope.py`): HTTP/HTTPS only; exact-origin
  allowlisting; explicit `PUBLIC` / `LOCAL_LAB`; DNS and address
  validation; redirect admission; embedded URL credentials rejected.
  v0.1.0 already rejects non-ASCII path/query before Transport, and
  rejects the remediated special-use IPv6 destination ranges (including
  NAT64 `64:ff9b::/96`).
- **Transport** (`src/boundary/transport.py`): httpcore with DNS/IP
  pinning; TLS SNI uses the real hostname; `retries=0`; bounded
  response bodies; optional timeouts (`None` means no BOUNDARY-imposed
  timeout); redirect revalidation; `OriginBoundCredentials` restricted
  to `Authorization` and `Cookie`; fail-closed
  `CROSS_ORIGIN_CREDENTIAL_REDIRECT`. Persistent connection reuse is
  not implemented.
- **Discovery** (`src/boundary/discovery.py`): uncredentialed `GET`
  only; `max_pages` / `max_depth`; HTML extraction of `a[href]`,
  `form[action]`, `script[src]`, `link[href]`. `crawl` is an async
  generator. There is no `DiscoveryResult`.
- **Passive** (`src/boundary/passive.py`): HSTS; nosniff; enforced CSP;
  frame protection; cookie `Secure`; `SameSite=None` without `Secure`.
  Kinds are `MISCONFIGURATION` and `HARDENING`. These are observations,
  not confirmed vulnerabilities.
- **Evidence** (`src/boundary/evidence.py`): `ResponseEvidence`
  (status, requested target, final target, body length, body SHA-256;
  no headers or body bytes); `FindingEvidence` pairing.
- **Authorization** (`src/boundary/authorization.py`): library only.
  Delivered: `Identity`, `AuthorizationCase`, `request_as` (GET
  hardcoded), `ResponseComparison`, `compare_response_evidence`,
  `AuthorizationObservationKind`, `AuthorizationObservation`. Pair
  sequencing exists only as a test helper
  (`_observe_completed_pair` in
  `tests/test_authorization_observation.py`). Production M6 forbids
  `run_authorization_case` and `AuthorizationEngine` as non-goals.
  `boundary scan` does not invoke this module.
- **Scan** (`src/boundary/scan.py`): `ScanConfig` (no field defaults,
  no secrets) -> `run_passive_scan` ->
  `ScanResult(findings=tuple[FindingEvidence, ...])`. `scan.py` does
  not import `authorization`.
- **Reporting** (`src/boundary/reporting.py`): `project_report_target`,
  `ScanReport`, `render_scan_report_json`, `render_scan_report_sarif`.
  Query redaction is `?REDACTED`. Fingerprints and `evidence_id` are
  omitted. SARIF 2.1.0 `level` is always `"note"`. No file writer. No
  GitHub upload. Authorization observations are not mapped.
- **CLI** (`src/boundary/cli.py`): `boundary scan` only.
  `--format {text,json,sarif}` (default `text`). No `--output`.
  `main()` returns `None` on success. Argparse errors are
  `SystemExit(2)`. Scan, URL, scope, and transport failures propagate
  as exceptions (traceback; typical process status 1). Findings never
  affect the process status.

### Reuse directly in v0.2.0

`ScanConfig`, `run_passive_scan`, `ScanResult`; `build_scan_report` and
the JSON/SARIF renderers; `ReportUrl` / `project_report_target`;
`Identity`; `OriginBoundCredentials`; `request_as`;
`compare_response_evidence`; `AuthorizationObservation` including
locked kinds and `authorization.pair.projection.v1`; `RequestLimits`;
`require_allowed_origin`; the existing `boundary scan` flag set.

### Do not reuse as

A vault, a verdict engine, a second scope engine, or a generic finding
type. Do not put credentials on `ScanConfig`. Do not merge
`AuthorizationObservation` into `FindingEvidence` or `ReportFinding`.
Do not overload `boundary scan`.

## 2. Dependency graph

Product order: **M9 fully, then M10 slices, then M11 as documentation**.
That is governance order (`AGENTS.md`: one approved milestone at a
time), not attractiveness order.

Library `run_authorization_case` does not need M9. The M10 CLI does:
it must share exit codes, stderr mapping, and `--output`.

```text
v0.1.0 frozen
    -> M9  CLI / CI contract (`boundary scan`)
    -> M10a library `run_authorization_case`
    -> M10b authorization report projection
    -> M10c `boundary compare` (uses M9 + M10a + M10b)
    -> v0.2.0 release

M11 is a chapter in this file. It produces no production module.
```

What each milestone produces for the next:

- **M9** produces the process contract M10 CLI must share: exit 0/1/2,
  stderr for known typed failures, atomic `--output`, stdout silence
  when writing a file.
- **M10 library** needs M6 primitives only. It is the production loop
  ADR 0006 left as a caller-side composition.
- **M10 reporting** needs M8 `ReportUrl`. In-memory
  `AuthorizationObservation.target.url` still carries the raw query;
  anything that leaves the process must be a projection.
- **M11** does not produce primitives required by M9 or M10. Existing
  `Origin` allowlists, `RequestLimits`, `Identity`, and the M10 JSON
  document are the foundations. A manifest, inventory, or rate limiter
  now would be attractiveness ordering.

## 3. M9 — Developer / CI ergonomics

Share of v0.2.0 work: **25%**.

User problem: v0.1.0 reports are deterministic, but the process is not
CI-safe. Operators rely on shell redirection (encoding and atomicity
hazards on Windows), uncaught tracebacks, and an undocumented “exit 0
means the scan ran” convention.

### 3.1 Exit-code contract (MUST)

Do not invent severity, confidence, or “findings mean failure”.
Passive findings are `hardening` / `misconfiguration` observations.
SARIF already locks `level` to `"note"`. Treating “HSTS missing” as
the same non-zero status as “DNS failed” makes CI undebuggable and
pretends a severity model exists.

Locked product contract:

- **0** — command completed: the scan finished and output was emitted,
  including the zero-finding case
- **1** — known execution or output failure:
  `UrlValidationError`, `ScopeValidationError`, `TransportError`,
  report projection/render `ValueError`, `--output` I/O error
- **2** — usage error: unchanged argparse `SystemExit(2)`

Findings present or absent must **never** change the exit status in
v0.2.0. Operators who want a findings gate inspect JSON outside
BOUNDARY.

Catch only those typed failures at the CLI adapter. Do not
`except Exception`. Library `run_passive_scan` stays exception-in /
result-out. There is no `ScanError` type.

Do not print a report on failure. Do not rewrite a failure as zero
findings. Preserve the intent of
`tests/test_cli_scan.py::test_scan_failure_is_not_rewritten_as_zero_findings`;
the assertion changes from “the exception propagates out of `main()`”
to “process status 1, empty stdout, no report build”.

Catching generic `ValueError` is too broad. Map the typed Scope / URL /
Transport errors and `--output` `OSError`. Let unexpected `ValueError`
traceback unless a specific constructor error is proven to be operator
input. Prefer a tight list.

#### M9a implementation note (do not lock the mechanism yet)

The product contract above is locked. The **internal** way `boundary`
turns that contract into a process status is not.

M9a must verify test-first, at process level against the installed
entry point (`[project.scripts] boundary = "boundary.cli:main"`):

1. Prefer returning an integer from the thin CLI entry point if the
   installed console-script wrapper correctly converts that return
   value into the process exit status.
2. Otherwise use the smallest explicit `SystemExit` boundary.

Do not lock `return int` versus `raise SystemExit` in this roadmap
before that RED process-level test proves the installed entry-point
behavior. Do not add `--output` in the same slice.

### 3.2 `--output` (MUST)

- Optional path. Omitted: today’s stdout behavior (renderer text plus
  the trailing newline `print` already adds).
- Set: write that same document to the path; **stdout stays empty** on
  success. No dual write. No “wrote report.json” chatter.
- Applies to `text`, `json`, and `sarif` identically.
- **Overwrite** if the file exists (CI reruns). No prompt. No append.
- **Do not create parent directories.** Missing parent is exit 1, no
  stdout fallback.
- **Atomic:** write a sibling temporary file in the same directory,
  then `os.replace` onto the destination. A crash mid-write must not
  leave a truncated destination that looks like a successful report.
- Path `-` is not stdout. Omit `--output` for stdout.
- Encoding: UTF-8, `\n` newlines (never locale encoding). JSON and
  SARIF remain ASCII via the existing renderers.
- Write failure after a successful scan: exit 1; do not reprint the
  report on stdout. The scan cannot be undone; the command did not
  complete its output contract.
- No GitHub upload, no pretty-print, no `--fail-on-findings`.

### 3.3 stdout / stderr

- Success without `--output`: report on stdout, stderr empty.
- Success with `--output`: stdout and stderr empty; the file holds the
  document.
- Failure: stdout empty; one diagnostic line on stderr; no JSON/SARIF
  fragment.

Error lines keep today’s property: Scope and Transport messages are
static strings (no URL or query interpolation).

### 3.4 Determinism

No new timestamps, run ids, or hostnames. `ScanReport` bytes remain
the source of truth. File bytes must equal stdout bytes for the same
scan (plus the single trailing newline already added by `print`).

### 3.5 Security

- `--output` must not log argv, target queries, or credentials
  (`boundary scan` still has none).
- Do not add credential, identity, cookie, header, or profile flags to
  `boundary scan`.

### 3.6 Tests required (RED first)

M9a (exit codes, no `--output` yet):

- completed scan with findings → process status 0
- completed scan with zero findings → process status 0 (findings are
  not a failure)
- argparse missing required flag → 2, no findings line
- `TransportError` / `UrlValidationError` / `ScopeValidationError` → 1,
  empty stdout, message on stderr, no `build_scan_report`
- process-level check of the installed entry point, used to choose
  `return int` versus `SystemExit` (see implementation note)

M9b (`--output`):

- writes the exact renderer document plus newline; stdout empty
- existing destination overwritten
- missing parent fails; no stdout fallback
- write error does not fallback to stdout
- query token absent from file and stderr
- `scan -h` documents `--output`; still omits `--cookie`, `--github`,
  `--fail-on-findings`

### 3.7 Explicitly deferred from M9

- severity thresholds
- `--fail-on-findings`
- GitHub Actions / `upload-sarif`
- configuration files
- timeout numeric defaults (omitted timeout remains `None`; changing
  that would break the v0.1.0 flag contract)
- scan wall-clock deadline
- `mkdir -p`
- pretty JSON
- changing default `--format` from `text`

## 4. M10 — Authorization workflow integration

Share of v0.2.0 work: **70%**.

User problem: M6 can compare two identities only if a caller
hand-writes the loop. `boundary scan` must stay uncredentialed.
Operators have no supported, scope-gated, query-safe way to run one
pair.

**Surface: library first, then CLI, in separate slices. Never a silent
branch inside `run_passive_scan`.**

### 4.1 Library (MUST) — `run_authorization_case`

Add one function on `src/boundary/authorization.py` named
`run_authorization_case`. M6 deferred the loop until a real production
consumer existed. M10 is that consumer.

M6 tests currently list `run_authorization_case` as a forbidden
speculative name. M10 replaces that absence check with behavioral
tests. That is contract promotion, not weakening. Keep forbidding
`AuthorizationEngine`, login/vault/cookie-jar types, and
`observe_from_error`.

```text
AuthorizationCase
    -> require_allowed_origin(case.target, allowed_origins)
    -> request_as(baseline) -> capture_response_evidence
       -> drop TransportResponse
    -> request_as(comparison) -> capture_response_evidence
       -> drop TransportResponse
    -> compare_response_evidence
    -> AuthorizationObservation
```

Inputs (explicit, no hidden defaults):

- `case: AuthorizationCase` (already requires distinct identities and
  a `TargetUrl`)
- `baseline_credentials: OriginBoundCredentials | None`
- `comparison_credentials: OriginBoundCredentials | None`
- `allowed_origins`, `policy`, `resolver`, `limits: RequestLimits`,
  `max_redirects`

`None` credentials mean anonymous. The library therefore permits:

- anonymous vs authenticated
- authenticated vs anonymous
- authenticated A vs authenticated B
- both `None` (two anonymous GETs) — allowed at the library boundary;
  the CLI product adapter rejects that case (section 4.3)

Call `require_allowed_origin` before any request (same pre-network
gate as `ScanConfig`). Every request goes through `request_as` →
`request_with_redirects`. No `crawl`, no `request_once`, no second
HTTP client. GET only; no request body; no mutating methods.

Lock production `rule_id`, `observation`, and `rationale` to the
strings already used in tests:

- `rule_id`: `authorization.pair.projection.v1`
- equivalent: “Baseline and comparison identities produced equivalent
  captured response projections.” / “Equivalent projections are an
  authorization anomaly requiring human review, not a confirmed
  IDOR/BOLA.”
- distinct: “Baseline and comparison identities produced distinct
  captured response projections.” / “Distinct projections are not a
  demonstration that access control worked.”

Callers must not supply verdict prose.

Execution is sequential. Baseline is requested first. If the baseline
request does not produce `ResponseEvidence`, the comparison request is
not attempted.

### 4.2 Completed pair vs incomplete pair

A pair is **completed** when both identities produce a
`ResponseEvidence`. Two completed HTTP responses always yield a
`ResponseComparison` and exactly one `AuthorizationObservation`.

HTTP 200 vs HTTP 403 are two completed HTTP responses. They therefore
produce a normal deterministic `ResponseComparison`. Because
`status_equal` is false, the observation kind is normally
`DISTINCT_PROJECTION`. That pair is not incomplete. Distinct status
codes are comparison facts, not a vulnerability verdict and not an
execution failure.

A pair is **incomplete** only when one of the requests does not
produce `ResponseEvidence`, for example because of:

- `ScopeValidationError`
- `UrlValidationError`
- `TransportError`
- credential redirect containment
  (`CROSS_ORIGIN_CREDENTIAL_REDIRECT`)
- another approved execution failure

Incomplete pairs produce **no** `AuthorizationObservation`. The
original error propagates unchanged. A thrown transport, scope, or URL
error is never rewritten as `DISTINCT_PROJECTION`,
`EQUIVALENT_PROJECTION`, or any other observation.

`CROSS_ORIGIN_CREDENTIAL_REDIRECT` is an incomplete pair (the named
identity’s request did not complete), not an observation that the
comparison identity was denied.

### 4.3 CLI (MUST, later slice) — `boundary compare`

Do not overload `boundary scan`. Help text must state that this emits
an **observation**, not a vulnerability verdict.

Required arguments:

- positional `target`
- `--allow-origin` (repeatable)
- `--address-policy`
- `--max-redirects`
- `--max-body-bytes`
- `--baseline-identity`
- `--comparison-identity`

Optional timeouts map onto `RequestLimits` exactly as `boundary scan`
does (`None` when omitted). Reuse M9 `--format {text,json}` and
`--output`. **No SARIF in M10** (would invite mixing with
`ReportFinding` or inventing severity).

Do not add `--max-pages` or `--max-depth`. This workflow is not
discovery.

#### Credential files

`--header Authorization:...` and secret values on argv are rejected:
shell history, CI logs, and process lists would hold secrets.

Smallest mechanism without a vault:

- `--baseline-credentials-file PATH`
- `--comparison-credentials-file PATH`
- File contents are secrets. Argv holds only paths.
- Format: bytes file; optional `Authorization:` and/or `Cookie:`
  lines; names matched case-insensitively; allowlist identical to
  `OriginBoundCredentials`; `\n` / `\r\n`; no comments; no other
  header names; no JSON.
- CLI performs I/O. A small pure helper turns `(Origin, header byte
  pairs)` into `OriginBoundCredentials`. Domain validation stays in
  Transport.
- Bind origin to `target.origin` after `parse_target_url`.
- Do not persist, log, `repr`, or copy credentials into observations
  or reports.
- Do not chmod-enforce (Windows). Document operator file permissions.
- No stdin (`-`), no password prompt, no `.netrc`, no vault, no login.

Env-var names as an alternate channel are deferred (second parser).
Recommend writing a temp file from CI secrets first.

#### Credential-less compare — CLI product rule

Library orchestration may still pass `None` for either or both
credential arguments.

The `boundary compare` CLI must **not** omit both credential sources
simultaneously. Two named identities executing exactly the same
anonymous request are not a meaningful operator comparison.

Locked CLI rule:

- at least one of `--baseline-credentials-file` or
  `--comparison-credentials-file` is required
- one side may omit its file (anonymous vs authenticated, either
  direction)
- both sides may supply files (authenticated A vs authenticated B)
- both sides authenticated is **not** required

This validation belongs to the CLI / product adapter. It is not a
Scope rule and not a Transport rule. `run_authorization_case` must not
reject both-`None` in order to enforce a CLI convention.

Omitting both files is a usage failure (exit 2 if argparse can
express it; otherwise the same documented usage path, not a scan
execution failure after network I/O). No HTTP request is issued.

### 4.4 Output (MUST)

In-memory result is `AuthorizationObservation`: two
`ResponseEvidence` values, four comparison booleans, and kind.

Process output must be a new reporting projection in
`src/boundary/reporting.py` that reuses `project_report_target`:

- `build_authorization_report`
- `render_authorization_report_json`
- allowlisted JSON: schema, kind, rule_id, redacted target and both
  `final_target` values, identity ids, both response projections
  (status, body_length, body_sha256), the four booleans, observation,
  rationale
- omit `fingerprint` (it hashes raw `TargetUrl.url`, same reason as
  M8)
- do not `dataclasses.asdict` the observation
- text format: kind, identity ids, four booleans, observation line;
  URLs only as `ReportUrl` if present at all

`scan.py` still must not import `authorization` or `reporting`.
`reporting.py` may import authorization types the same way it already
imports `ScanResult`.

### 4.5 What must NEVER be a vulnerability verdict

- `equivalent_projection` / `distinct_projection`
- equal or unequal status, length, digest, or final target
- HTTP 200 vs HTTP 403 (a completed `DISTINCT_PROJECTION`, not a
  confirmed IDOR/BOLA, and not an incomplete pair)
- `CROSS_ORIGIN_CREDENTIAL_REDIRECT` (incomplete pair / transport
  failure)
- exit code 0 (the command completed; that is not “safe”)
- any AI or LLM reading of the JSON

CLI must not print `vulnerable`, `IDOR`, `BOLA`, `confirmed`, CVSS, or
severity. Exit 0 on a completed observation regardless of kind.

### 4.6 Security

- Scope admits every hop. An allowlisted cross-origin redirect with
  credentials still aborts the pair.
- GET only.
- Credentials never appear on `ScanConfig`, `ScanResult`, reports,
  fingerprints, or help examples.
- `boundary scan` still has no identity or credential flags.
- Authorization remains opt-in via `compare`. Extra GETs are not a
  default scan profile.

### 4.7 Explicitly deferred from M10

- IDOR/BOLA verdicts
- AI
- login / account creation
- cookie jar
- vault
- `POST` / `PUT` / `PATCH` / `DELETE`
- feeding crawl URLs into cases automatically
- authorization SARIF
- `--fail-on-equivalent`
- custom API-key credential headers
- concurrency
- requiring both sides to be authenticated

## 5. M11 — Bug Bounty foundations (documentation only)

Share of v0.2.0 work: **5%** (this chapter). **0% production code.**

Complete Bug Bounty Mode is not justified by the v0.1.0 architecture.
Discovery does not accumulate inventory; there is no rate limiter;
`Identity` is already the public profile; reporting is a per-run
projection, not a pack. Implementing a “mode” would invent planners,
plugins, and program scraping that the product rules forbid.

No M11 production module. No Bug Bounty Mode implementation in
v0.2.0.

### Classification

- **Scope manifest** — useful but defer. A JSON file listing
  `--allow-origin`, `--address-policy`, and limits that **loads into
  existing `Origin` / `ScanConfig` / compare inputs** would help
  multi-asset programs. It must not validate addresses, DNS, or
  redirects. Scope remains the only engine. Deferred because CLI flags
  already express scope and a file parser is new attack surface. If
  revisited in v0.3: stdlib JSON only, fail-closed unknown keys, no
  YAML.
- **Request / rate budget** — useful but defer. `RequestLimits`,
  `DiscoveryLimits`, and `max_redirects` already bound one scan and
  one pair (exactly two GETs). Missing: inter-request delay,
  `max_requests` across mixed workflows, wall-clock deadline. Needed
  before any future multi-URL authorization crawl. Not required to
  ship one-pair M10. Do not change omitted timeout = `None`.
- **Endpoint inventory** — useful but defer. `crawl` yields pages and
  `ScanResult` drops clean ones by design (ADR 0003 / 0007). A
  visited-`TargetUrl` tuple would help later coverage claims, but it
  mutates `ScanResult` and reporting cardinality. Premature as a
  persisted catalog. Do not add `DiscoveryResult`.
- **Identity profile** — premature as a new type. `Identity` is the
  public profile. A file that bundles secrets with labels is a vault.
  M10 credential files are per-run execution material, not stored
  profiles.
- **Evidence bundle / handoff** — premature as a zip/pack. M8
  JSON/SARIF and M10 authorization JSON are the deterministic handoff.
  A multi-artifact pack waits until a consumer needs more than one
  document.

### Explicitly deferred (M11 and later)

- autonomous pentesting
- exploit chains
- active injection
- automatic account creation / login
- browser automation
- wildcard program scraping
- vulnerability submission APIs
- AI planning / execution
- HackerOne / Bugcrowd integrations
- generic plugin architecture

## 7. Architecture delta

Remain a modular monolith (ADR 0001). Reject `engines/`, `services/`,
plugin systems, agent frameworks, dependency-injection containers,
persistent databases, and event buses. There is no concrete proof they
are required.

Planned module-level delta:

- `src/boundary/cli.py` — exit mapping, `--output`, `compare`
  subcommand, credential-file read, at-least-one-file CLI check
- `src/boundary/authorization.py` — `run_authorization_case` and
  locked observation prose constants
- `src/boundary/reporting.py` — authorization report builder and
  renderer; reuse `ReportUrl`
- `src/boundary/scan.py` — no change
- `src/boundary/scope.py`, `transport.py`, `discovery.py`,
  `passive.py`, `evidence.py` — no change unless a tiny pure helper is
  required for credential-line parsing (prefer CLI + existing
  `OriginBoundCredentials`)

Import rules:

- `scan.py` must not import `authorization` or `reporting`
- `authorization.py` must not import `discovery`, `passive`, or `cli`
- CLI may call scan, authorization, and reporting as a thin adapter

No new runtime dependencies.

## 8. Test strategy

Preserve: tool → evidence → reproduce → regression test → minimal
fix/feature. Tests before implementation. No public Internet. Fake the
transport hop and resolver; do not mock `run_authorization_case` or
the renderers under test.

### M9

RED slices in `tests/test_cli_scan.py`, plus a focused output-file

## 11. Major risks

- Credential files still leak if operators commit them, upload them as
  CI artifacts, or pass world-readable paths. BOUNDARY can refuse to
  put secrets on argv; it cannot be a vault.
- Catching `ValueError` at CLI is too broad. Keep the typed-error
  list tight.
- M6 absence tests fail when `run_authorization_case` is added.
  Replace them deliberately. Do not delete neighboring
  “no engine / no vault” guards.
- Dynamic pages make `equivalent_projection` rare and
  `distinct_projection` noisy. That is an accepted M6 limit, not an
  M10 bug. Do not add semantic similarity.
- Query strings remain on in-memory `AuthorizationObservation` and
  fingerprints. Only the report projection is safe to export. Same
  residual risk as M8 path tokens and `body_sha256`.
- Authorization issues extra GETs (ADR 0006). Product surface stays
  opt-in via `compare`.
- `--output` overwrite can destroy a file if the path is wrong.
  Boring, documented, CI-correct.
- Env-var-name credential aliases for CI remain an open, non-blocking
  question. Files first.

- argparse error → 2
